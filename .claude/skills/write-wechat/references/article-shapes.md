# 公众号文章骨架

先根据读者任务选择一种主要骨架，必要时局部组合。骨架决定信息顺序，不决定固定句式。

## 痛点解法

适合教程、效率、运营和避坑：具体摩擦 → 常见做法为何失效 → 核心方法 → 执行与验证 → 失败信号和边界 → 下一步。

必须交代前置条件与完成标准，不能只列步骤。

## 故事复盘

适合项目、人物和真实案例：目标与约束 → 选择与代价 → 转折 → 结果证据 → 原因与反事实 → 可迁移判断。

只使用用户提供或有来源的事件；材料不够时改用观察或判断开头。

## 清单指南

适合工具、资源和准备清单：选择标准 → 按场景组织条目 → 每项价值与限制 → 快速选择路径 → 不适用情况。

每项回答“适合谁、解决什么、代价是什么”，避免堆积薄条目。

## 对比决策

适合产品与方案选择：决策问题 → 比较标准 → 逐维度证据 → 关键权衡 → 按场景推荐 → 都不适合的条件。

先定义标准，再给结论。用条件式建议代替无条件“最好”。

## 热点解读

适合新闻、政策和行业变化：已确认事实与时间线 → 为什么现在发生 → 对不同读者的实际影响 → 常见误读 → 后续观察信号。

新增价值来自解释、边界和影响，不是复述新闻。

## 观点论证

适合行业判断和反常识命题：明确命题 → 常见看法的不足 → 证据与推理 → 最强反方 → 成立条件 → 读者需要改变的行动或判断。

观点应可反驳且有边界，情绪不能替代论证。

## 开头、标题与结尾

开头尽快交代真实问题、冲突、变化、判断或结果。不要用宏大时代背景、虚构朋友或空悬念预热。

标题候选应采用不同机制，例如直接任务、对象与结果、对比选择、风险避坑、真实数字、新闻影响或观点命题。选择时依次判断：正文能否兑现、对象是否明确、角度是否具体、张力是否诚实。

结尾选择一个真实任务：给决策、给下一步、给观察信号、说明边界，或回扣开头。避免换一种说法重复全文。

## 移动端节奏

- 多数段落保持 1 至 4 句，一段处理一个重点；长句保留因果与条件，短句承担转折。
- 每几个自然段提供一次信息推进，例如事实、例子、动作、判断标准或反方。
- 列表用于真正并列的信息，表格超过 4 列时优先拆分。
- 小标题应推进判断或问题，不要只写“为什么重要”“具体步骤”。
- 粗体和金句只强调关键内容，不把整篇切成连续碎句。
