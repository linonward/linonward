<Step id="enforce-transitions" number={4} title="用状态机执行合法转换">

不要在各处分散写 `state.status = ...`。创建唯一转换入口，明确哪些边可以走，并在同一操作中追加带单调序号和时间戳的事件。

```typescript
const allowedTransitions: Record<AgentState["status"], AgentState["status"][]> = {
  running: ["completed", "failed", "blocked"],
  blocked: ["running", "failed"],
  completed: [],
  failed: [],
};

export function transitionState(
  state: AgentState,
  next: AgentState["status"],
  reason: string,
  now = new Date(),
): AgentState {
  if (!allowedTransitions[state.status].includes(next)) {
    throw new Error(`invalid state transition: ${state.status} -> ${next}`);
  }
  if ((next === "completed" || next === "failed" || next === "blocked") && !reason.trim()) {
    throw new Error("terminal transition requires a reason");
  }

  return {
    ...state,
    status: next,
    stopReason: next === "running" ? undefined : reason,
    events: [
      ...state.events,
      {
        sequence: state.nextEventSequence,
        recordedAt: now.toISOString(),
        type: "status_changed",
        detail: `${state.status} -> ${next}: ${reason}`,
      },
    ],
    nextEventSequence: state.nextEventSequence + 1,
  };
}
```

本章的状态机只管理运行生命周期；第 04 章把 `TaskPlan` 嵌入同一个 `AgentState`，计划步骤状态不能反向覆盖运行状态。最终完成还要在后续章节加入验收证据门禁。

</Step>

<Step id="test-state-machine" number={5} title="测试成功、失败和阻塞路径">

创建 `tests/state.test.ts`，固定时间并验证：`running → completed`、`running → failed`、`running → blocked → running`；终态不能恢复；空停止原因被拒绝；每次转换的 sequence 严格递增且 `recordedAt` 可解析。测试的是公开状态转换，不是 UUID 实现。

```typescript
it("records a blocked and resumed run without losing audit order", () => {
  const initial = createInitialState("检查 package.json", "/workspace");
  const blocked = transitionState(initial, "blocked", "approval_required", fixedTime);
  const resumed = transitionState(blocked, "running", "approval_granted", laterTime);

  expect(resumed.events.map((event) => event.sequence)).toEqual([1, 2, 3]);
  expect(resumed.status).toBe("running");
  expect(resumed.stopReason).toBeUndefined();
});
```

</Step>
